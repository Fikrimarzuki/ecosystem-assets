## 5. Token optimisation decisions

**Measured file sizes:**
- Skill metadata, always loaded: the description is 362 characters.
- `SKILL.md` body: 3.3 k characters.
- Each reference file: 1.6–3.5 k characters.
- All skill docs together: 21 k characters.

**What a task would load without the skill:**
- the style bible: 68.7 k characters;
- the Mom spec: 9.0 k;
- the feasibility report: 11.4 k;
- the v1 review: 4.9 k.

**Decisions:**
- **Progressive disclosure:** the routing table in `SKILL.md` sends each task to one or two references.
- **No duplication:** facts that already exist are referenced by path and section (style bible §13, spec §2–§4), not copied.
- **Compact script output:** each script prints a single summary line, so no large output enters the context.
- **Fixed known failures:**
  - the export no longer hangs and needs no manual polling loops;
  - matched-size comparison is one command instead of ad-hoc Krita scripts.

**Expected but not measured:**
- fewer repeated prompts;
- fewer review rounds;
- smaller per-task context: about 1–2 k tokens from the skill, against 20 k or more for reading the source documents.

Token figures are estimates (characters ÷ 4). Actual token use per session was not measured.

## 7. Limitations

- **Visual quality is unproven:** the skill has not yet been used to draw anything, so it is untested whether it improves Mom's look. That is M1.1d's job.
- **Guidance needs confirming:** the adult-vs-child numbers and the hair rules are general character-design guidance, labelled as starting points. They need confirming against Candidate B crops.
- **Heuristic warnings:** `check-svg.mjs` uses regular expressions, not a full XML parser, so its sticker-primitive warnings are hints. Run `xmllint` for XML validity.
- **Platform:** `export-png.sh` is macOS-specific (it uses `stat -f` and `sips`).
- **Duplicate ids remain:** they are still in `mom-head-v1.svg` and the eye experiment, because this milestone could not modify them.
